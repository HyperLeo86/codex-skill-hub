# 四维静态检查清单（skill-analyst）

用法：每个检查项记录「证据位置 + 结论」。结论只允许 ✅（通过）/ ⚠️（部分）/ ❌（不通过）。无法核验的标「待验证」。

## L 逻辑

| ID | 检查项 | 证据要求 |
| --- | --- | --- |
| L1 | 步骤有编号且顺序自洽，无「后置步骤依赖前置产物但排在前面」 | 步骤号与产物引用 |
| L2 | 每个决策分支都有出口（停止/降级/继续），无死节点 | 分支条件与出口 |
| L3 | 模式判断（Tool Wrapper/Generator/Reviewer/Inversion/Pipeline）与内容匹配 | 模式特征与反例 |
| L4 | 同一概念全文同名（术语/枚举/结论值），无两套词汇 | 两处以上引用 |
| L5 | 引用的 references/scripts/文件真实存在 | 路径与文件列表 |
| L6 | 循环/重试有终止条件（轮次上限/预算/门） | 循环描述 |

## U 可用性

| ID | 检查项 | 证据要求 |
| --- | --- | --- |
| U1 | description 是路由规则（做什么+何时用），正触发 ≥6 且反触发 ≥1 | description 原文 |
| U2 | 输出有固定结构/契约，验收 ≥3 条且可自动检查 | 输出与验收章节 |
| U3 | 失败降级 ≥3 个场景，每个有 fallback | 失败降级章节 |
| U4 | 敏感/付费/破坏性操作有确认门槛与权限最小化 | 相关步骤 |
| U5 | 有 token/时间预算或资源上限，无失控风险 | 预算表/worker 配置 |

## M 可修改性

| ID | 检查项 | 证据要求 |
| --- | --- | --- |
| M1 | SKILL.md 在预算行数内；细节下沉 references/scripts/assets | 行数与文件分布 |
| M2 | references 有渐进式披露（索引/按场景读取提示），非全量堆叠 | references 结构 |
| M3 | 与同级 skill 无触发重叠、职责边界清晰 | 同级目录对比 |
| M4 | 外部依赖（CLI/服务/密钥/其他 skill）声明了安装与降级 | 资源与依赖章节 |

## E 可进化

| ID | 检查项 | 证据要求 |
| --- | --- | --- |
| E1 | references/regressions.md 存在且有真实条目 | 账本内容 |
| E2 | 有 eval/测试用例或验收回归手段 | eval 目录/验收 |
| E3 | 有版本号+日期+CHANGELOG 与发布门 | 版本与发布章节 |
| E4 | 有模型升级适配条款（旧补丁可删性检查） | 相关条款 |

## 常见误判提醒

- 步骤多 ≠ 逻辑清晰；看门与出口
- 有 references ≠ 渐进式披露做得好（无索引时仍难加载）
- 有脚本 ≠ 设计合理（脚本可能没被流程调用）
- 无负面记录 ≠ 可靠（可能只是没人用）
