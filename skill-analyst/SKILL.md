# skill-analyst

**版本**：1.1（2026-08-07）

## 概览

对现有 Skill 做四维体检（逻辑/可用性/可修改性/可进化），输出带证据的问题清单与精准优化方案。分析只读；写入目标 skill 必须经用户确认。

## 触发与反触发

- 触发：分析一下这个 skill；帮我体检一下这个技能；看看这个 SKILL.md 哪里有问题；这个技能该怎么优化；帮我审查一下技能目录；这个 skill 的逻辑清晰吗；分析一下它的可用性和可维护性；对本地技能库做一次分析
- 反触发：创建/生成一个新技能；把技能发布到 GitHub；帮我检索世界上有没有现成方案

## 决定权（自由度 medium）

- 按伪代码/模板执行，参数可依上下文调整
- 静态事实以 scripts/analyze_skill.py 输出为准，禁止即兴重算
- 报告格式遵循 references/output-spec.md，内容允许合理变化
- 直接修改目标 SKILL.md 必须先得到用户确认

## 运行模式

- Quick（默认）：轻量体检，走阶段 0→1→2→4，输出四维摘要 + P0-P3 问题清单，适合单文件快查
- Full：完整分析，走阶段 0→6，输出 analysis.json + 节点图 + 优化计划 + eval 建议，含动态实证
- Batch：技能目录扫描（如「对本地技能库做一次分析」），先跑阶段 0 静态统计 + 四维快筛，再对 Top 异常目标做 Full
- Profile：身份卡模式，走阶段 0→1→2，输出一张身份卡（核心目的 / 意图 / 逻辑 / 实现效果 / 重要场景 / 注意事项），不做缺陷评分；模板见 references/profile-template.md

注意：analysis.json 的 mode 字段统一小写 `quick` / `full` / `batch`；正文展示用 Quick/Full/Batch。

## 工作流（六阶段）

0. **取证**：读目标 SKILL.md + references + scripts + 账本；运行 scripts/analyze_skill.py 收集确定性事实（行数/token/描述长度/引用文件存在性/脚本可执行位/版本行）
1. **拆逻辑**：把「步骤/决策门/循环/人工确认门」画成 Mermaid 节点图；做静态检查（模式判断、步骤顺序、死节点、不可达出口、缺门、词汇一致性、跨切面约束误当步骤）
2. **四维体检**：按 references/scorecard.md 对逻辑/可用性/可修改性/可进化打 ✅/⚠️/❌，每条结论附证据位置（文件名+行号/步骤号）
3. **动态实证**（仅 Full）：从契约挑 1–3 个真实任务最小试跑；抓 JSONL 做确定性检查（命令/产物/顺序）+ rubric（--output-schema）+ token/耗时计量；多次运行可转事件日志做一致性检查；grader 与 executor 分离，防自我纠错假通过
4. **诊断分级**：P0（安全/资源失控/数据丢失）→ P1（逻辑不通/死链/缺门）→ P2（结构/一致性/体验）→ P3（措辞）；每条附根因、证据、建议
5. **精准优化**：按优先级给出改动方案与预期可测效果；用户确认后才写入目标文件；写入后重跑阶段 3 验证；同一目标的优化-验证循环最多 3 轮，超限暂停并交用户决策
6. **固化**：把 eval 建议交付给目标技能、追加目标账本（若允许）、更新分析报告版本

## 验收（来自契约）

- 报告四维（逻辑/可用性/可修改性/可进化）各有至少 3 项可核验指标，且每条结论附证据位置（行号/步骤号/文件名）
- Profile 模式输出身份卡六要素（核心目的/意图/逻辑/实现效果/重要场景/注意事项），每项附证据位置
- 问题清单按 P0-P3 分级，每条附根因与证据；无证据的判断必须标注「待验证」，禁止凭感觉下结论
- 每个目标 skill 输出一张 Mermaid 节点图，含决策门、循环、人工确认门
- 优化计划按优先级排列，每项改动指明预期可测效果与验证方式
- 分析保持只读；直接修改目标 SKILL.md 必须经用户确认

## 失败降级

- 目标 skill 只有 SKILL.md，无 references/scripts → 基于现有文件分析，并在报告中标注未覆盖资源
- 无法运行真实任务（无环境/无许可/无密钥） → 动态实证降级为静态检查，结论标注「待验证」，不编造运行结果
- 目标路径缺失或错误 → 停止并询问用户，不猜测路径
- 目标 skill 引用不存在的文件或脚本 → 作为 P1 问题记录（死链/不可达出口），并核对其余引用
- 被分析对象是 skill-forge 或本技能自身 → 使用独立外部检查器与清单，避免自我辩护偏差（grader 与 executor 分离）

## 维护纪律

- 优化-验证循环最多 3 轮，超限暂停并交用户决策
- 大模型版本升级后，先重跑 references/regressions.md 全部场景，再检查为旧模型能力打的补丁是否可删；不可删的必须注明适用模型版本
- 修改 SKILL.md / description 后必须运行 scripts/check_triggers.py 做触发回归

## 资源

- scripts/analyze_skill.py：静态事实收集器（确定性，先跑）
- scripts/check_triggers.py：触发回归检查器（description 改动后必跑）
- references/profile-template.md：身份卡模板（Profile 模式）
- references/checklist.md：四维静态检查清单
- references/scorecard.md：四维评分卡模板
- references/mode-map.md：模式×阶段映射与节点图规范
- references/output-spec.md：analysis 报告 JSON 结构
- references/regressions.md：本技能回归账本

## Token 预算（契约：200 行 / 2000 token）

SKILL.md ≤200 行 / ≤2000 token；description ≤1024 字符；references 按需加载，单文件 ≤10k 词。
