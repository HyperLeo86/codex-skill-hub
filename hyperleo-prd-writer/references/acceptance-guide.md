# AC 写法规范

## 四条硬规则

1. **可测试**：测试能写用例。
2. **无歧义**：禁用「尽量 / 必要时 / 合理 / 友好 / 等」。
3. **覆盖异常**：失败怎么处理。
4. **可追溯**：AC 编号关联需求编号（AC-3.1 ↔ R3 / FR-003）。

## GWT 模板

```gherkin
Given <前置条件/输入>
When <动作/触发>
Then <可观察结果>
And <附加结果/异常路径>
```

## 强制词

- `must`：必须满足（验收阻塞项）
- `should`：应有，缺失需说明理由
- `may`：可选增强
- 禁止：尽量、大概、合理、必要时、更友好、等（列表末尾省略义）

## 例子

好：

```gherkin
Given 2000 行 CSV，其中 5 行缺必填字段
When 提交导入
Then 30 秒内返回结果页，成功 1995 / 失败 5
And 失败报告含行号/字段名/原因
```

坏：`导入时要对数据做校验，尽量友好地提示错误`

## AC 与 DoD 区分

- AC：单条需求成功的条件。
- DoD：团队级质量门槛（代码评审、测试通过、文档更新），不属于某条 AC。
