# 检索世界（v1.4）

**版本**：1.4（2026-08-03）

## 定位

用户想到一个点子或需求时，先找到世界上已有的最佳现成方案，让用户直接使用。你的任务不是评估想法是否值得创业，不是创造新方案，也不是做市场分析。

成功标准：给出「用哪个、为什么、怎么开始」。

## v1.4 五项升级（对比 v1.3）

1. **查询变体扩展**：术语地图阶段每个核心概念生成 3–5 个变体查询（同义词 / 口语 / 学术 / 反搜 / 英文），全部进入引擎扫描，解决单查询语义脆弱导致的漏检。
2. **多路合并重排**：三引擎 + 变体结果合并后，按「相关度 × 来源独立性（被几个独立查询/引擎命中）× 双源支持度」统一排序，取 top 10 进初筛。
3. **历史库回灌**：扫描前先浏览历史索引，按相似度取 1–3 份历史报告，其相关证据标注「历史库」直接进入候选清单。
4. **检索日志**：report.json 增加 `retrieval_log`（每个变体查询 / 引擎 / 命中数）与 `history_reused`，输出页可见，支持事后复盘与指标计算。
5. **验证反馈补搜**：Tavily 验证不过但硬约束满足的候选，触发一轮定向补搜（查询 = 候选名 + 核心特征），新增有用候选 < 2 则停止。

## 决策模型

每个候选方案只给五种结论之一：

| 结论 | 含义 |
| --- | --- |
| 直接用 | 成熟且匹配，推荐立即试用 |
| 改改用 | 接近但需要少量改造，估算改动量 |
| 只借鉴 | 不直接可用，但思路或模块可复用 |
| 淘汰 | 不满足约束或明显劣于替代 |
| 待验证 | 信息不足，需要人工确认或试跑 |

## 运行模式

- **普通模式（默认）**：单轮检索，走工作流 1–6 步，总时长 ≤ 2 小时。
- **Loop 模式（深度扫描）**：当用户说「深度扫描」「深扫」「Loop 模式」，或需求需要完整解构、对标分析、构建路线图时启用，默认 2–3 轮：
  - **第 1 轮**：同普通模式（Exa + Tavily + 内置搜索 + 渠道矩阵）。
  - **第 2 轮**：从第 1 轮 top 候选的 README / 官网 / Related / Alternatives 中提取新术语与机制名，生成新查询再扫描，结果合并去重。
  - **第 3 轮（可选）**：跨域结构词扫描与缺口验证（补齐上轮未覆盖的渠道或维度）。
  - **收敛规则**：一轮新增有用候选 < 2 则提前停止；总轮次上限 3；总时长 ≤ 3 小时。
- report.json 必须记录 `mode`（normal / loop）与 `rounds`；输出页会标注扫描模式与轮次。

## 工作流

### 1. 需求翻译（5 分钟）

确认或推断四个问题：

1. 最终想要的结果是什么？
2. 需要哪种类型：现成产品 / 开源库 / 算法或方法 / 数据集 / API 服务 / 教程或技能？
3. 输入、输出、使用场景分别是什么？
4. 硬约束：成本、隐私、语言、环境、规模。

类型决定渠道：找库去 GitHub 和包管理器，找产品去工具导航，找方法去论文和教程，找数据去数据集站。信息不足时先按合理假设继续，把假设记入 report.json 的 `assumptions`。

### 2. 术语地图（10 分钟）

生成 15–20 组搜索词（中英各半），覆盖：核心问题词、用户口语词、技术学术词、相邻方案词、反查组合（"X alternative"、"X vs Y"、"how to do X without building"、"X 替代"）。

**v1.4 追加**：对每个核心概念再生成 3–5 个**变体查询**（不同措辞 / 不同语言 / 不同抽象层级），写入检索日志。变体越多，单查询漏检风险越低。

### 3. 渠道矩阵扫描（30–60 分钟）

**v1.4 追加（历史库回灌）**：扫描前先浏览历史目录 `index.html` 与 `*/report.json`，按主题相似度取 1–3 份历史报告；相关证据（历史候选、结论、来源）标注「历史库」直接进入候选清单。

**引擎策略（三引擎）**：

1. **Exa（主引擎 · 语义检索）**：所有查询先用 `python3 scripts/exa_search.py "查询词" --num 10 --text` 跑一轮，中英文原样传词。Exa 擅长把模糊需求映射到具体工具/项目，适合概念型查询与垂直长尾发现。
2. **Tavily（第二引擎 · 结构化交叉验证）**：候选确认阶段用 `python3 scripts/tavily_search.py "查询词" --num 5` 交叉验证关键候选（存在性、成熟度、替代方案）。Tavily 输出结构化 JSON，覆盖偏泛化，适合验证而非主发现。
3. **Codex 内置搜索 + 渠道矩阵**：按 [references/channels.md](references/channels.md) 执行，覆盖 GitHub、中文社区、反搜组合（"X alternative"）、awesome 列表、论文与跨域同构，负责找头部成熟方案与系统性覆盖。

规则：

- 三路结果**合并、按 URL 去重**后进入同一候选清单（去重是显式子步骤）。
- 每个候选必须有真实来源和链接，禁止编造；Exa 结果偏新项目，判断成熟度仍需双源交叉验证。
- 若历史目录已存在，先浏览 `index.html` 排除已查主题；中文渠道至少占三分之一。
- 只记录：名称、链接、一句话、来源。不评估。
- **v1.4 追加（多路合并重排）**：去重后按「相关度 × 来源独立性（命中独立查询/引擎数）× 双源支持度」评分排序，取 top 10 进入初筛；排序依据写入检索日志。

### 4. 方案卡评估（15–30 分钟）

**两阶段筛选（先淘汰，再精评）**：

- **初筛（宽筛 → 淘汰）**：硬约束不满足（成本/隐私/语言/环境/规模任一不符）、无真实来源、明显废弃（archived / unmaintained）的候选直接淘汰，不进方案卡。
- **精评（3–7 个候选）**：按 [references/output-spec.md](references/output-spec.md) 填写 report.json。
  - 成熟度 L0–L5：离「直接用」有多远（L3/L4 首选，L5 遵循标准）
  - 匹配四维：输入、输出、场景、约束（✅/⚠️/❌）
  - **引用审计**：每个关键结论（成熟度、许可、活跃度）必须能指回来源，且来源必须**支持**该结论（不只是提到该词）；成熟度 L3+ 必须有两个独立来源（Exa / Tavily / 内置搜索 / 渠道矩阵任意组合）；无法指回来源的结论标「待验证」
- 排序：匹配度 × 可用度

### 5. 最小试跑（30 分钟）

对首选方案：5 分钟看文档/demo → 15 分钟跑最小用例 → 10 分钟查真实评价（Reddit / GitHub Issues / 知乎等）。无法实际运行时，明确说明并把结论降级为「待验证」。

**v1.4 追加（验证反馈补搜）**：Tavily 验证不过、但硬约束满足且相关度高的候选，不直接淘汰——用「候选名 + 核心特征」做一轮定向补搜（Exa 或内置搜索），新增有用候选 < 2 则停止。

### 6. 输出与归档

1. 将结果写入 report.json（含 mode 与 rounds；Loop 模式还需 loop_notes；v1.4 还需 retrieval_log 与 history_reused）
2. 运行 `python3 scripts/build_report.py <report.json 路径> [--history-dir <目录>]`
3. 默认历史目录 `~/Documents/solution-scout-history`；用户指定时用用户路径
4. 告诉用户结果页与历史索引页的完整路径

## 停止规则

- 发现一个 L4 且四维匹配的方案 → 直接进入最小试跑，不再扩展候选
- 全部渠道零发现 → 换一组搜索词再扫一轮；仍无 → 结论「大概率无现成方案，自建合理」
- 全程控制在 2 小时左右
- Loop 模式下追加：一轮新增有用候选 < 2 → 提前停止；总轮次 ≤ 3；总时长 ≤ 3 小时
