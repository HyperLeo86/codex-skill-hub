# 前向测试协议（TDD）

## 原理

技能是行为文档。验证技能 = 验证「有技能 vs 无技能」时行为是否按预期改变。

## 最小循环（RED → GREEN → REFACTOR）

### RED（无技能基线）

1. 从意图卡挑 1 个真实任务，写成独立 prompt
2. 用**全新上下文**的 subagent 执行（不给技能、不给预期答案、不给你的结论）
3. 记录：任务完成度、行为偏差、失败点

prompt 模板：

```text
请完成以下任务：[任务描述，与真实用户请求同构]
不要假设额外工具；遇到不确定时说明你的选择。
```

### GREEN（带技能）

1. 相同任务，prompt 改为：`请使用 /path/to/skill 完成：[任务]`
2. 用全新上下文重跑
3. 对比 RED：行为是否改变、失败是否消失、产物是否达标

### REFACTOR（堵漏洞）

- 找到 agent 仍会绕过的点，在 SKILL.md 加显式条款
- 对每条失败写「防复发条款」，而不是补一句「要小心」
- 重跑 GREEN 确认没有回归

## 反合理化清单

Agent 常用借口 → 必须显式反驳或写入纪律：

| 借口 | 反驳 |
| --- | --- |
| 「我稍后补测试」 | 测试是验证门的一部分，缺测试 = 未完成 |
| 「这个场景太简单不用写」 | 简单场景正是触发面，必须覆盖 |
| 「用户不会那样说」 | 触发句来自真实用语，先测再说 |
| 「脚本报错但输出看起来对」 | 输出必须经确定性检查，不能只靠目测 |

## 验收标准

- GREEN 与 RED 相比行为明显改变
- 意图卡中的验收标准全部可检查且通过
- check_skill.py 无 ERROR
- 已知边界被明确写出，而非隐藏

## 进阶（复杂技能）

- 复杂技能跑 2–3 个跨场景任务（正常 / 边界 / 反触发）
- 用两个独立 subagent 并行跑，交叉看产物
- 每次迭代后清理测试产物，避免污染下一轮
