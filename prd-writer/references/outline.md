# 8 模块骨架与内容约束卡

## 使用

- 完整版（新产品/新模块）展开全部 8 模块。
- 迭代版（单功能新增/优化）按裁剪映射删减，不要求写满。

## 模块卡

1. **基本信息**：版本、作者、评审人、背景链接、变更记录（谁/何时/改了什么/为什么/影响/谁确认）。
2. **问题陈述**：三段式（现状与证据 / 影响与代价 / 时机与约束）；证据必须给出来源，否则标 `[ASSUMPTION]`。
3. **目标与成功指标**：业务结果指标 + 交付结果指标；每个指标带口径与观察周期；至少 1 个反指标（不想牺牲什么）。
4. **范围与非范围**：Must / Should / Not now / Assumptions（含不成立时的处置）。
5. **用户与场景**：角色/权限/目标；主路径 1 条写透；高频异常；关键约束（审计/合规/设备）。
6. **需求拆解**：User Story（谁 + 想要 + 为了）；业务规则（条件/例外/边界/口径）；每条规则 ≥1 个例子（example-first.md）；交互状态/字段/错误提示由技能自动补全。
7. **验收标准**：AC 用 GWT；每条需求至少 1 条 AC；AC 与 DoD 分开；可追溯到目标/范围/规则。
8. **上线与运营**：埋点口径、灰度/回滚触发条件、权限与培训、风险清单（依赖/数据/性能/合规与应对）。

## 裁剪映射（迭代版）

| 模块 | 迭代版处理 |
| --- | --- |
| 1 基本信息 | 保留 |
| 2 问题陈述 | 简化为「本次变更背景」 |
| 3 目标与指标 | 只写本次指标 |
| 4 范围 | 写「本次范围/非范围」 |
| 5 用户与场景 | 只写受影响角色与场景 |
| 6 需求拆解 | 全量 |
| 7 验收标准 | 全量 |
| 8 上线与运营 | 只写受影响上线项 |

## MVP 闸门

默认只展开核心功能（🔴）；增强项（🟡）与远期（⚪）只列名称与理由，不展开细节。
