# RFI 闭环协议

## 为什么

PRD 交付后开发中必然出现新歧义；没有正式通道就会回到口头猜测。

## 规则

1. 每个歧义 = 一条 RFI：编号 `RFI-001` 递增。
2. 字段：提出人 / 日期 / 问题描述 / 影响范围（关联 FR/AC）/ 建议方案 / 甲方答复 / 状态。
3. SLA：默认 24 小时；48 小时可配置；由项目在交接时定。
4. 超时升级：SLA 内未答复 → 按「默认假设」继续（记录在 RFI + assumptions.md），并升级甲方负责人。
5. 答复后：若改变范围/口径/AC → 开变更单（CR-001），更新 PRD 版本 + 变更记录；不改变则关闭 RFI。
6. 口头变更 = 无效；必须落成 RFI/CR。

## 默认假设机制

- 每个 RFI 必须给「默认假设」（先按什么口径继续），避免流程停摆。
- 默认假设写入 assumptions.md 并标 `[RFI-00x]`。
