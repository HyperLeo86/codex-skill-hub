# 报告模板（三块精简版）

## 输出结构（固定顺序，正文 ≤150 词）

```markdown
# <span style="color:#d4a017">错误复盘日志</span>

## <span style="color:#e06c75">YYYY-MM-DD · <任务一句话></span>

| 类别 | 内容 |
| --- | --- |
| <span style="color:#569cd6">**事实**</span> | <日期时间与当时事实> |
| <span style="color:#d19a66">**技术性错误/缺失**</span> | 1. <概念名>：<为什么错><br>2. <概念名>：<为什么错> |
| <span style="color:#98c379">**人文性错误/概念**</span> | <概念> —— <一句话解释>（可无） |
```

规则：
- 技术性错误 1-2 条，能出两个出两个，出不了就出一个，不灌水
- 人文性错误/概念 0-1 条，找不到贴切概念就不出
- 不输出错误模型、背景说明、模板或目录
- 颜色为内联 HTML；主题不渲染时表格结构仍然清晰

## 落盘决策树

| 经验形态 | 落点 | 例子 |
| --- | --- | --- |
| 可机械检测 | lint / ast-grep 规则 | 禁止用 `Array.from(set).length` |
| 简短、每次必守 | AGENTS.md / CLAUDE.md | 批量写入上限 100 行 |
| 多步流程 + 判断 | 新 Skill 或追加现有 Skill | 发布后验证所有服务版本 |
| 项目一次性 | 不落盘，留在报告 | 具体函数名修复 |

## 反自我合理化清单

- 出现「以后小心点」→ 重写为可检查动作
- 根因停在「模型幻觉」→ 下钻到最早可拦截层
- 想凑满 2 条技术性错误 → 只有 1 条有把握就只出 1 条
- 想硬凑人文概念 → 找不到贴切概念就不出
- 想写背景/模板/错误模型 → 用户明确不要，删除
- 想跳过去重检查 → 同概念必须计数而非新建
