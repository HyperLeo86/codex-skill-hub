# hyperleo-ash-verdict

**版本**：1.0（2026-08-07）

## 概览

失败复盘只输出三块，**不要更多**：
1. **事实**：日期时间 + 当时发生了什么
2. **技术性错误/缺失**：1-2 条（能出两个出两个，出不了就出一个，不灌水）
3. **人文性错误/概念**：0-1 条（能出一个出一个，出不了就不出）

另按 DDC 循环追加一条精简错误日志（表格形式），供回顾与收敛。

## 触发与反触发

- 触发：9 条真实说法（见 description）
- 反触发：premortem（未失败的风险预防）、纯修复不分析、成功任务的普通总结

## 决定权（自由度 medium）

- 五步流程顺序不可跳过；取证手段与措辞可依上下文调整
- 输出严格限制为三块 + 日志条目；**禁止输出错误模型、长篇分析、背景说明或模板**
- 验收标准是唯一事实源：不达标必须降级或停止，不得美化结果

## 工作流（五步）

### 1. 意图还原

- 用用户原话重建目标一句话 + 成功标准 + 约束（内部步骤，不写入最终输出）
- 若执行行为与意图矛盾，做意图-行为一致性核验：
  A 意图被静默替换 / B 执行偏差 / C 用户表述偏差

### 2. 证据收集与时间线

- 证据优先级：会话轨迹/日志 > git 历史/工作区状态 > 用户陈述 > 推断
- 只标关键节点：开始 → 第一个偏离点 → 关键决策点 → 失败点
- 无证据标「未知」，禁止脑补；轨迹缺失时用当前上下文 + 用户补充

### 3. 技术性错误/缺失定位

- 把「失败点上的设计决策」与 references/knowledge-fault-set.md 逐域匹配：
  该决策本该用到哪个概念/框架？
- 命中 → 输出该概念；未命中 → 创建新概念条目并标注「新增」
- 标缺失类型：缺知识 / 不完整 / 误解 / 遗漏 / 错误信念 / 矛盾
- 判断是否「知识型失败」：若只是执行失误（slip-up），不进错误清单
- 因果纪律：机制可陈述 + 判别证据 + 反事实检验，缺任一标「待验证」
- 数量：最多 2 条；只有 1 条有把握就只出 1 条

### 4. 人文性错误/概念提炼

- 把技术性错误映射到一个人文/哲学概念（如盲人摸象、灯下黑、刻舟求剑），
  映射表见 references/failure-patterns.md
- 找不到贴切概念就**不输出**，绝不硬凑

### 5. 输出与日志

- 输出顺序：事实 → 技术性错误/缺失 → 人文性错误/概念
- 用表格 + 颜色呈现（模板见 references/report-template.md），标题可加颜色
- 按 references/error-log.md 追加一条精简日志（默认路径为 Obsidian
  错误复盘日志；用户拒绝落盘则只在对话内给出文本）
- 同概念重复出现：不新建条目，计数 +1
- 正文 ≤150 词（不含日志条目）

## 验收（来自契约）

- 输出只有三块：事实、技术性错误/缺失（1-2 条）、人文性错误/概念（0-1 条）
- 不输出错误模型或其他分析章节
- 每条技术性错误命中故障集或创建新条目，并标注缺失类型
- 错误日志按精简模板（表格）追加一条
- 正文 ≤150 词

## 失败降级

- 无轨迹 → 当前上下文 + 用户补充，标证据缺口
- 故障集匹配不到 → 新建概念条目，标「新增」，不硬套
- 证据不足 → 标「待验证」+ 补证实验
- 找不到人文概念 → 该块不输出
- 仅抱怨未要求复盘 → 先确认；仅需修复则转交排障
- 用户拒绝写文件 → 对话内给日志文本，不落盘
