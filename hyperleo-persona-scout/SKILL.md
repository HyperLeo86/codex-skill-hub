# hyperleo-persona-scout

**版本**：0.2.0（2026-08-08）

## 概览

关系情报版人物分析：事实不变，意义随关系身份变化。四层架构 = 意图卡 → 事实层 → 透镜层 → 建议层。

## 触发与反触发

- 触发：帮我查一下这个人是谁；调研一下这个明星的履历；这个人是什么来头？；给我一份 XXX 的人物画像；快速了解一下这个人；帮我查一下这个 GitHub/微博/推特作者是谁；这个企业家/学者/网红什么背景？；以潜在合作方/对手/老师/陌生人的身份帮我分析这个人
- 反触发：深度人肉或收集非公开隐私（住址/电话/未公开信息）；把人物蒸馏成可对话的思维模型 Skill；查公司/产品/组织本身的调研；需要付费数据库或会员墙的深挖

## 决定权（自由度 medium）

- 按伪代码/模板执行，参数可依上下文调整
- 输出格式遵循模板，内容允许合理变化

## 工作流

0. **意图输入**：已有意图卡（含 Relationship）→ 直接进入；只有人名 → 调用 `hyperleo-intent-recognition` 出卡；不可用 → 以 `[ASSUMPTION] Relationship=陌生人` 出卡并标待确认。有重名风险 → 输出消歧声明。
1. **事实层检索（一次）**：并行多引擎（内置 + Exa/Tavily，渠道见 `references/channels.md`），完成 5 区块：身份速览 / 履历时间线 / 代表作与关键资产 / 网络足迹 / 证据分级（A/B/C/D，模板见 `references/dossier-template.md`）。
2. **透镜选择**：按意图卡 Relationship 从 `references/lens-registry.md` 选透镜（老师/陌生人/博弈对手/潜在商业伙伴/自定义）。用户中途换身份 → 事实层缓存复用，只重跑透镜层。
3. **定向补查**：按透镜核心问题集补 ≤1 轮检索（如对手查冲突记录、伙伴查招投标/合作评价）。
4. **建议层**：按 `references/advice-templates.md` 输出关系视角分析 + 行动建议，每条建议必须追溯事实层证据。
5. **缺口检查**：事实 5 区块 + 透镜 + 建议共 7 区块，每块至少 1 条；空洞 → 补一轮；仍无 → 「待确认」。
6. **交付**：输出关系情报卡（Markdown）+ 来源列表；用户需要文件时存到 outputs/。

## 验收（来自契约）

- 每个事实条目带来源 URL 与置信度（A/B/C/D），无来源事实不写入正文
- 输出含事实层/透镜层/建议层，透镜由意图卡 Relationship 决定，不自问意图
- 意图卡缺失时用 [ASSUMPTION] 标注默认关系，不阻塞放行
- 建议必须可追溯到事实层证据，无证据的建议不写
- 存在重名歧义时，开头给出消歧声明
- 中文正文 ≤ 1800 词，超出部分进附录

## 失败降级

- 重名/同名人物混淆 → 用 handle、地域、职业、作品等线索消歧；仍歧义则输出候选列表并分别给证据
- 检索渠道缺失（无 Exa/Tavily key） → 降级为内置搜索 + 官方站点直连，并在检索日志中标注缺失渠道
- 目标人物信息极少或非主流 → 输出浅层画像并标记 LOW 置信度，提示走长尾渠道或后续扩展
- 主流媒体语言非中文 → 双语检索，保留原文证据，翻译内容标注「译」
- 输入只有孤名、无任何线索 → 先调用 hyperleo-intent-recognition 出意图卡，再开始检索
- 来源事实冲突（年龄/职务/作品等） → 并列冲突来源，取多源一致值并标注分歧
- 无意图卡且意图识别不可用 → 以 [ASSUMPTION] 默认 Relationship=陌生人，标待确认
- 用户中途更换关系身份 → 事实层缓存复用，只重跑透镜层与建议层
