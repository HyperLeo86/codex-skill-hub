# 打造技能 v1.2.0（范式跃迁版）

**版本**：1.2.0（2026-08-03）

## 跃迁点

v1.1.0 的瓶颈：质量依赖作者写作水平，验证靠一次性人工判断，进化靠记忆。

v1.2.0 换坐标系：**技能 = 可测试的行为契约，而不是说明文档。**

- 取消：手工撰写长正文 → 契约生成
- 取消：一次性验证 → 回归账本 + A/B 测试
- 取消：从零设计结构 → 统一契约与路由表
- 改变成本关系：质量随「测试覆盖 × 反馈回灌」提升，不随写作字数提升；token 成为可计量的预算项

## 工作流（契约闭环，5 步）

### 1. 压缩：一页契约

先写契约（模板见 references/skill-spec.md），**禁止先写正文**：

- 触发面：≥10 个真实触发句 + 反触发
- 输入 → 输出 + 验收检查（可观察、可自动判）
- 约束与自由度（低 / 中 / 高）
- 失败模式：预测 ≥3 个失败点及降级路径
- token 预算：SKILL.md ≤300 行，references 按需加载

### 2. 生成：规格驱动

用 `scripts/build_skill.py <spec.json> --out <目录>` 生成合规骨架（SKILL.md 路由表 + 目录 + description），再人工补「模型不知道的程序性知识」，删除模型已知的常识。

正文与契约冲突时，改契约，不硬塞正文。

### 3. 验证：测试即质量

运行 `scripts/check_skill.py`（token / 结构 / 孤儿引用 / 描述触发）。

执行 A/B 前向测试（协议见 references/validation.md）：
- A 臂：无技能，跑 1 个真实任务（基线）
- B 臂：带技能，跑同一任务
- 比较：行为差异、完成率、token 增量、产物质量

达标线：B 明显改变行为且通过验收；未达标 → 回到第 1 步改契约，最多 3 轮。

### 4. 回灌：失败模式账本

每次真实使用后，把失败记入 `references/regressions.md`（一行式：场景 / 失败 / 修复），最多保留 10 条，旧的删除或归档。

下次创建或升级前先查账本：命中已知失败模式 → 必须写入防复发条款。

### 5. 固化：交付与版本

交付摘要：契约、测试结果、token 计量、已知边界、版本号（patch / minor / major）。

升级时先跑回归账本中的全部场景，全绿才发布新版本。

## 操作子对照（跃迁机制在本技能中的落地）

| 操作子 | 落地方式 |
| --- | --- |
| 删除 | 删掉模型已知的 prose；SKILL.md 只留路由 + 纪律 + 验收 |
| 标准化接口 | 一页契约 + 固定路由表，所有技能同一结构 |
| 可编程化 | build_skill.py 从 spec 生成合规骨架 |
| 反馈 | A/B 测试 + 回归账本，把失败转成防复发条款 |
| 稀疏采样 | token 预算表 + 按需加载 references |
| 容错重建 | 每步有降级路径：脚本失败 → 手工；参考缺失 → 内联要点 |

## Token 预算表

| 文件 | 预算 | 超标动作 |
| --- | --- | --- |
| SKILL.md | ≤300 行 / ≤2500 token | 内容沉到 references |
| description | ≤100 词 | 只留触发词与任务词 |
| references/* | 单文件 ≤10k 词 | 加目录 + grep 提示 |
| scripts/* | 执行不进上下文 | 直接运行 |

## 资源

- `scripts/build_skill.py`：规格驱动生成器（用法见文件头）
- `scripts/check_skill.py`：质量与 token 检查器（用法见文件头）
- `references/skill-spec.md`：一页契约模板 + 示例
- `references/validation.md`：A/B 协议 + 回归账本格式

## 铁律

1. 不先写正文，先写契约
2. 没有 A/B 或至少 RED→GREEN 测试，不算完成
3. 不创建 README.md / CHANGELOG.md 等人类文档
4. 回归账本命中过的失败，禁止无防护重现
5. 卡住超过 2 轮即汇报，不编造验证结果
