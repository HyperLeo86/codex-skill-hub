# 角色与人工门

## 角色分工

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| Worker（骑士） | 按契约实现、跑验证、返回结构化交接 | 不发布、不审查自己、不启动子 agent、不擅自扩大范围 |
| Reviewer（学士） | 只读审查，输出发现与证据位置 | 不修改代码、不执行发布、不把两轴合并排名 |
| 御前会议（父会话） | 调度、核对交接、执行发布、维护队列状态、回填证据 | 不直接编辑源码；发布权唯一 |
| 用户（国王） | 人工门决策、授权不可逆操作 | 决策前由御前会议呈现事实、选项、影响与建议 |

角色冲突检查：同一任务中同一执行体不得同时担任 Worker 与 Reviewer；发布者不得兼任 Worker。违反即契约校验失败，重新分配后再启动。

## 人工门清单（任一触发即停队列）

| 场景 | 要求 |
| --- | --- |
| 需求/范围/架构无法确认 | 呈现已验证事实与选项，等用户决定 |
| 权限或凭据缺失 | 不猜测、不绕过，等用户提供或授权 |
| 未授权费用 | 等用户明确批准金额与范围 |
| 破坏性操作（删除/重置/强推） | 等用户明确同意 |
| 证据不一致（交接 vs 事实源） | 停止核对，等用户裁定 |
| 第三轮审查仍阻塞 | 等用户决定，禁止第 4 轮 |
| 验证额度耗尽后失败 | 等用户决定是否扩额 |
| 子 agent 协议失败/无交接 | 评估恢复或停止，等用户 |
| 状态无法确认 | 不推进，先确认 |

## 平台适配（角色不变，调用方式不同）

| 能力 | Codex | pi/其他 |
| --- | --- | --- |
| 启动 worker/reviewer | spawn_agent（fresh） | subagent / agents |
| 异步推进/等待 | followup_task + wait | async + 完成通知 |
| 人工恢复 | 答复后 followup_task | supervisor reply/resume |
| 隔离工作区 | git worktree 或独立目录 | 按平台能力 |

Preflight 探测不到的能力必须降级（串行/单会话/停止），禁止假装可用。
