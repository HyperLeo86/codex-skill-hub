# 谱系追踪（为什么是它、以前试过什么）

## 四技法

1. **决策考古**：当前方案为什么被采用？查 ADR / git log / 替换记录
2. **失败尝试分析**：说「X 不行」时，问失败的是整体还是某方面、当时约束是什么、现在是否已变
3. **复兴检测**：新方案可能是旧方案换名字；查历史先例（如 RAG 版式提取 = pdftotext -layout 的 AI 复兴）
4. **范式迁移映射**：记录迁移前后得失，避免重复踩坑

## 输出模板（候选的 lineage 字段）

```
## 谱系：<方案>
**来源**：<前身/分支/重写>
**为什么出现**：<解决了前身的什么失败>
**关键教训**：<许可/架构/社区教训>
**复兴点**：<现在环境变了什么>
```

## 在本技能中的用法

- 每个精评候选补 1–3 句 lineage（不用长篇）
- 若候选是 AGPL/GPL 或曾废弃，lineage 必须说明根源（如 PyMuPDF 的 AGPL 源自 MuPDF 商业结构）
- 整体报告顶层的 `lineage` 字段回答：「为什么这个生态长这样」
