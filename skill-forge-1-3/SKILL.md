# 打造技能 v1.3.0（范式跃迁版）

**版本**：1.3.0（2026-08-03）

v1.2.0 → v1.3.0：契约校验化、账本种子、决定权条款、description 升级、版本纪律、检查强化。完整变更见仓库级 CHANGELOG（skill 文件夹之外）。

## 跃迁点

技能 = 可测试的行为契约，而不是说明文档。质量随「测试覆盖 × 反馈回灌」提升，不随写作字数提升；token 是计量的预算项。

## 工作流（契约闭环，5 步）

### 1. 压缩：一页契约

先写契约（模板见 references/skill-spec.md），**禁止先写正文**：

- 触发面：≥6 个真实触发句 + ≥1 反触发（模板、生成器、检查器同一数字）
- 输入 → 输出 + 验收检查（可观察、可自动判）
- 约束与自由度（low / medium / high）
- 失败模式：预测 ≥3 个失败点及降级路径
- token 预算：SKILL.md ≤300 行，references 按需加载

### 2. 生成：规格驱动

用 `scripts/build_skill.py <spec.json> --out <目录>` 生成合规骨架：SKILL.md（路由 + 决定权条款 + 触发表 + 验收）+ references/regressions.md 账本种子 + agents/openai.yaml，再人工补「模型不知道的程序性知识」，删除模型已知的常识。

正文与契约冲突时，改契约，不硬塞正文。

### 3. 验证：测试即质量

运行 `scripts/check_skill.py <skill-dir> [spec.json]`（token / 结构 / name=目录 / 账本存在 / spec 校验 / 孤儿引用 / 一层深 / 可执行位）。

先做 **RED→GREEN**：用一个故意违规的样本确认检查器会失败（RED），再修到通过（GREEN）。

再执行 A/B 前向测试（协议见 references/validation.md）：
- A 臂：无技能，跑 1 个真实任务（基线）
- B 臂：带技能，跑同一任务
- 比较：行为差异、完成率、token 增量、产物质量

达标线：B 明显改变行为且通过验收；未达标 → 回到第 1 步改契约，最多 3 轮。

### 4. 回灌：失败模式账本

每次真实使用后，把失败记入 `references/regressions.md`（一行式：场景 / 失败 / 修复），最多保留 10 条，旧的删除或归档。

下次创建或升级前先查账本：命中已知失败模式 → 必须写入防复发条款。

### 5. 固化：交付与版本

交付摘要：契约、测试结果、token 计量、已知边界、版本号（patch / minor / major）。

版本号 + 日期写 SKILL.md 头部一行；完整变更记录放 skill 文件夹之外（仓库级 CHANGELOG），不进运行时文件。

发布门三绿：check 全绿 + 账本全绿（无未修复）+ A/B 或 RED→GREEN 达标。三绿不满足，不发布新版本。

## 决定权（本技能自己的宪法）

- 结构、预算、命名以 `scripts/check_skill.py` 为准：禁止为通过检查而放宽规则
- 验收标准是唯一事实源：不达标必须降级或停止，不得美化结果
- 生成器能确定的部分（骨架 / 账本 / description），禁止手写覆盖后再声称合规
- 脚本能确定的部分（同输入同输出），禁止 agent 即兴重算或覆盖

## 操作子对照（跃迁机制在本技能中的落地）

| 操作子 | 落地方式 |
| --- | --- |
| 删除 | 删掉模型已知的 prose；SKILL.md 只留路由 + 纪律 + 验收 |
| 标准化接口 | 一页契约 + 固定路由表，所有技能同一结构 |
| 可编程化 | build_skill.py 从 spec 生成合规骨架 + 决定权条款 + 账本种子 |
| 反馈 | A/B + RED→GREEN + 回归账本，把失败转成防复发条款 |
| 稀疏采样 | token 预算表 + 按需加载 references |
| 容错重建 | 每步有降级路径：脚本失败 → 手工；参考缺失 → 内联要点 |

## Token 预算表

| 文件 | 预算 | 超标动作 |
| --- | --- | --- |
| SKILL.md | ≤300 行 / ≤2500 token | 内容沉到 references |
| description | ≤1024 字符 | 只留触发词与任务词 |
| references/* | 单文件 ≤10k 词 | 加目录 + grep 提示 |
| scripts/* | 执行不进上下文 | 直接运行 |

## 资源

- `scripts/build_skill.py`：规格驱动生成器（用法见文件头）
- `scripts/check_skill.py`：质量、token、spec 与账本检查器（用法见文件头）
- `references/skill-spec.md`：一页契约模板 + 示例
- `references/validation.md`：A/B 协议 + 发布门
- `references/regressions.md`：回归账本（生成器自动种子化）

## 铁律

1. 不先写正文，先写契约
2. 没有 A/B 或至少 RED→GREEN 测试，不算完成
3. 不在 skill 文件夹内创建 README.md / CHANGELOG.md 等人类文档；变更记录放文件夹之外
4. 回归账本命中过的失败，禁止无防护重现
5. 卡住超过 2 轮即汇报，不编造验证结果
6. 发布门三绿不满足，不发布新版本
